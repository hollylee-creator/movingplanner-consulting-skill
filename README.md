# movingplanner-consulting-skill

오늘의집 무빙플래너 파일럿 상담 대응 스킬.

## 업데이트 모델 — 두 갈래

| 무엇을 고쳤나 | 재업로드 필요? | 반영 시점 |
|---|---|---|
| `references/service-facts.md` (마감일·적립률·링크) | **아니오** | 다음 대화부터 |
| `references/case-scripts.md` (복붙 스크립트) | **아니오** | 다음 대화부터 |
| `SKILL.md` (원칙·톤·케이스 라우팅) | 예 | 재업로드 후 |
| `sync.sh` | 예 | 재업로드 후 |

숫자·마감일처럼 실제로 자주 바뀌는 값은 전부 `references/`에 있으므로, **일상적인 갱신은 커밋만 하면 끝**이다.
`SKILL.md`는 원칙과 톤이라 파일럿 중에 거의 안 바뀐다.

## 일상 갱신

```bash
# 예: 멤버십 마감일이 바뀜
vi references/service-facts.md
git commit -am "멤버십 무료가입 마감 9/30으로 연장"
git push
```

끝. 다음 대화에서 `sync.sh`가 최신 파일을 받아온다.

커밋 메시지에 "왜 바꿨는지"를 남기면 그게 파일럿 학습 로그가 된다.

## SKILL.md를 고쳤을 때

푸시하면 Actions가 zip을 만들어 `latest` 릴리스에 붙인다.
릴리스에서 `moving-planner-consult.zip`을 내려받아 claude.ai 설정에서 스킬로 다시 업로드한다.

## 동작 조건

- 저장소가 **public**이어야 한다. private이면 raw fetch가 404가 나고 번들 사본으로 폴백한다.
  (토큰을 스킬 파일에 넣는 방법은 쓰지 말 것 — 스킬은 평문으로 읽힌다.)
- 대화에서 **코드 실행이 켜져 있어야** 한다. 꺼져 있으면 폴백.
- 폴백 시에도 상담은 되지만 값이 과거일 수 있어, 스킬이 상담사에게 확인을 요청하도록 되어 있다.

## 알려진 정합성 이슈

- `case-scripts.md` #8과 마감 브로드캐스트가 적립률을 "10%"로 단정한다.
  `service-facts.md`는 구간제(200~300만 10% / 300만 초과 5%)이며 "무조건 10%" 표현을 금지한다.
  → 스크립트를 "200만 원어치면 20만 원" 예시 형태로 고치는 것이 안전하다.
