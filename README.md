# movingplanner-consulting-skill

오늘의집 무빙플래너 파일럿 상담 대응 스킬.

## 업데이트 모델 — 두 갈래

| 무엇을 고쳤나 | 재업로드 필요? | 반영 시점 |
|---|---|---|
| `references/service-facts.md` (마감일·적립률·링크) | **아니오** | 다음 대화부터 |
| `references/case-scripts.md` (복붙 스크립트) | **아니오** | 다음 대화부터 |
| `SKILL.md` (원칙·톤·케이스 라우팅) | 예 | 재업로드 후 |
| `sync.sh` | 예 | 재업로드 후 |

숫자·마감일처럼 실제로 자주 바뀌는 값은 전부 `references/`에 있으므로, **일상적인 갱신은 재업로드 없이 main에 합치기만 하면 끝**이다. (아래 '일상 갱신' 참고)
`SKILL.md`는 원칙과 톤이라 파일럿 중에 거의 안 바뀐다.

## 일상 갱신

고친 내용은 먼저 작업용 브랜치에 올라간다. 브랜치는 원본(`main`)과 별개로 쓰는 임시 사본이다.
**`main`에 합쳐야 비로소 상담사에게 반영된다.** 상담 때 최신 값을 받아오는 곳이 `main`이기 때문이다(`sync.sh`).
작업용 브랜치에만 올라간 내용은 아직 아무에게도 적용되지 않는다.

### 흐름

1. 정책 변경을 Claude에게 알려준다.
2. Claude가 무엇을 왜 바꿀지 먼저 보여준다. 확인해 주면 작업용 브랜치에 올린다. (올린 뒤 어느 브랜치인지 알려준다.)
3. 아래 방법으로 `main`에 합친다.
4. 합친 다음 대화부터 반영된다. (`references/` 안의 파일만 고쳤다면 재업로드는 필요 없다.)

### main에 합치는 방법 (깃헙 웹사이트에서, 코드는 몰라도 된다)

1. 저장소 페이지 https://github.com/hollylee-creator/movingplanner-consulting-skill 를 연다.
2. 상단에 노란 배너로 `Compare & pull request`(합치기 요청 만들기) 버튼이 뜨면 누른다.
   - 배너가 없으면 `Pull requests` 탭 → `New pull request`를 누르고,
     왼쪽(base)은 `main`, 오른쪽(compare)은 작업용 브랜치로 고른다.
3. 제목과 설명이 채워져 있는지 보고 `Create pull request`를 누른다.
4. 화면 아래 "무엇이 바뀌는지"(Files changed 탭)를 한 번 훑어본다. Claude가 보여준 내용과 같으면 된다.
5. 초록색 `Merge pull request` → `Confirm merge`를 누른다. 이 순간 `main`에 반영된다.
6. 합치기가 끝나면 Claude에게 알리면 된다. 필요하면 다음 대화에서 반영됐는지 같이 확인한다.

합치기 전에 내용이 틀린 걸 발견하면 Merge를 누르지 말고 Claude에게 고쳐 달라고 하면 된다.
이미 합친 뒤라면 고친 내용을 같은 방식으로 한 번 더 합치면 된다.

커밋(저장 기록) 메시지에 "왜 바꿨는지"를 남기면 그게 파일럿 학습 로그가 된다.

## SKILL.md를 고쳤을 때

`SKILL.md` 또는 `sync.sh`를 고쳤으면 스킬을 **다시 업로드해야** 반영된다.

zip은 Claude가 만들어서 대화창에 파일로 준다. 그걸 내려받아 claude.ai 설정에서
스킬로 다시 업로드하면 끝. (자동 빌드 Actions는 없다 — 예전 README에 있던
"푸시하면 Actions가 zip을 만든다"는 설명은 사실이 아니었고 삭제했다.)

zip 안쪽 구조는 이 형태여야 한다:

```
moving-planner-consult/
├── SKILL.md
├── sync.sh
└── references/
    ├── service-facts.md
    └── case-scripts.md
```

`references/` 안만 고쳤으면 zip은 필요 없다. main에 합치기만 하면 다음 대화부터 자동 반영된다.

## 동작 조건

- 저장소가 **public**이어야 한다. private이면 raw fetch가 404가 나고 번들 사본으로 폴백한다.
  (토큰을 스킬 파일에 넣는 방법은 쓰지 말 것 — 스킬은 평문으로 읽힌다.)
- 대화에서 **코드 실행이 켜져 있어야** 한다. 꺼져 있으면 폴백.
- 폴백 시에도 상담은 되지만 값이 과거일 수 있어, 스킬이 상담사에게 확인을 요청하도록 되어 있다.

## ⚠️ 적립 구조 — 이 저장소에서 가장 자주 틀리는 것

이 문단은 과거 사고 기록이다. 적립 문구를 손대기 전에 반드시 읽는다.

**적립은 구간제이고, 각 요율은 그 구간에 해당하는 금액에만 붙는다(초과분 방식).**
누적 구매액 전체에 한 요율을 곱하는 게 아니다.

| 누적 구매 구간 | 요율 |
|---|---|
| 100만원 미만 | 적립 없음 |
| 100~200만 | 1% |
| 200~300만 | 10% |
| 300만 초과 | 5% |

적립은 100만원부터 시작하고, **최대 46만원**(누적 1,000만원 지출 시)이다.

**공식 계산기 확인값 — 예시가 필요하면 이 숫자만 쓴다:**

| 누적 구매 | 적립 |
|---|---|
| 200만원 | 1만원 |
| 300만원 | 11만원 |
| 330만원 | 12만 5천원 |
| 1,000만원 | 46만원 (최대) |

### 과거 사고 (2026-09 정정)

- **"200만원이면 20만원 적립"은 20배 틀린 문구였다.** 실제 적립은 1만원이다.
  고객 발송 스크립트 4곳에 들어가 있었고, 전량 교체했다.
- **"적립률이 10%예요" 식 단정도 틀렸다.** 10%는 200~300만 구간에만 붙는다.
- 원인: 옛 팩트 시트가 1% 구간을 빼고 "200~300만 10%"만 보고 전체에 10%를 곱하는
  예시를 "안전한 예시"로 권했다. 그 안내 문장 자체가 오류의 출처였으므로 삭제했다.
- 최대 적립을 "45만원"으로 적은 것도 1% 구간을 뺀 계산 오류였다. 46만원이 맞다.

### 규칙

- 숫자를 암산하지 않는다. 상담사에게는 공식 '혜택 계산기'로 넘기는 게 1순위다
  (대표 페이지 https://ohou.se/moving-pass/intro 의 '혜택 계산기' 탭).
  예전 링크 link.ohou.se/ztai61 은 판매 종료된 9,900원 상품으로 연결되므로 쓰지 않는다.
- 200만원 이하 지출 고객에게 적립을 앞세우지 않는다. 200만원 지출 시 적립은 1만원이라,
  이 구간에선 환급 30,000P와 할인 쿠폰팩이 실제 주 혜택이다.
- 무빙패스 조건은 2026-10 기준 이용료 30,000원(즉시 30,000P 환급) · 180일 · 최대 30만원 할인 쿠폰팩이다.
  예전 조건(9,900원 · 90일 · 11/30 마감 · 배송비 쿠폰 5만원)은 폐기됐다.
- 팩트 시트에 없는 숫자는 추측하지 않고 담당자에게 확인한다.

## 신청 대행 경계 — 두 번째로 자주 틀리는 것

- **신청 대행 대상: 이사 · 입주청소 · 부분시공 · 종합시공 (4개뿐).** 상담사가 대신 접수한다.
- **고객 자가 신청: 인터넷 · 렌탈 · 멤버십(무빙패스).** 고객이 링크에서 직접 신청한다.
- 이 둘을 섞어 "인터넷도 신청해드릴게요"로 넘어가면 과약속이다.
