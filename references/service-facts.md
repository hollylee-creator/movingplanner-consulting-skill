# 서비스 팩트 시트 (메시지 작성 전 대조용)

> 파일럿 1R 기준. 숫자·링크·조건이 바뀌면 이 파일만 갱신하면 스킬 전체가 최신화된다.
> 변하는 값(마감일·적립률·한정 대상)과 안 변하는 로직(원칙·톤)을 분리해 관리할 것.

## 가치 정의 — 과약속 금지

- 플래너가 주는 것: 일정 정리 + 궁금증 응답 + 신청 대행 + 의사결정 코칭(고르는 기준·순서).
- **신청 대행 대상(2R부터): 이사 · 입주청소 · 부분시공 · 종합시공.** 상담사가 대신 접수한다.
- 대행의 취지: 서비스별로 견적을 따로 신청하면 정보를 여러 번 입력해야 하고 서비스 간 일정 조율이 어렵다. 주소·평형·희망 일정을 한 번만 받아 상담사가 신청서를 대신 작성·접수하고, 서비스 일시가 담긴 이사 일정표를 전달한다. (고객이 대행 개념을 이해 못 할 때 → `case-scripts.md` 케이스 19)
- **견적 신청은 계약이 아니다.** 견적을 받아보는 상담 신청이며, 견적을 본 뒤 진행 여부는 고객이 결정한다.
- **자가 신청으로 남은 것: 인터넷 · 렌탈 · 멤버십.** 고객이 딥링크에서 직접 신청. 여기엔 "신청해드릴게요" 금지.
- 플래너가 여전히 안 하는 것: 업체 선택 대행 ❌(매칭된 업체 중 선택은 고객), 견적 비교 대행 ❌.
- 30가지 체크리스트 = 신청자 전원 무료. 개인화 일정표·상담 = 선정(매칭) 고객 한정. 단, 플래닝중(카톡 채널에 인입된) 고객 모두에게는 일정표를 전달할 수 있다.
- 선정 안내: 신청해도 전원 상담 아님. 이사 임박 고객 우선 순차.

### 적립 — 구간제 (요율은 예전과 같음)

- **누적 구매액 기준 구간제. 각 구간 요율은 그 구간에 해당하는 금액에만 붙는다(초과분 방식).**

  | 누적 구매 구간 | 요율 | 구간 최대 |
  |---|---|---|
  | 100만원 미만 | 적립 없음 | - |
  | 100~200만 | 1% | 1만원 |
  | 200~300만 | 10% | 10만원 |
  | 300~1,000만 | 5% | 35만원 |

  적립은 100만원부터 시작한다. **최대 적립 46만원**(누적 1,000만원 지출 시 = 1만 + 10만 + 35만). 공식 계산기 슬라이더 상한도 1,000만원.

  **계산 예시(공식 숫자, 그대로 쓸 것):** 누적 330만원 → (100만×1%) + (100만×10%) + (30만×5%) = 1만 + 10만 + 1.5만 = **12만 5천원**

  참고용 환산표(내부 판단용, 고객에게 표로 주지 말 것):

  | 누적 구매 | 적립 | 실질 요율 |
  |---|---|---|
  | 200만원 | 1만원 | 0.5% |
  | 300만원 | 11만원 | 3.7% |
  | 330만원 | 12.5만원 | 3.8% |
  | 500만원 | 21만원 | 4.2% |

  ⚠️ **"200만 원어치면 20만 원 적립"은 완전히 틀린 문구다(실제 1만원, 20배 과장). 절대 쓰지 말 것.**
  ⚠️ "적립률이 10%예요" 식 단정도 금지. 10%는 200~300만 구간에만 붙는다. 페이지 문구도 '최대 10%'다.
  - 적립은 무빙패스 이용 기간(180일) 안에 **구매확정된** 금액 기준이다.
  - 코칭 포인트: 200~300만 구간이 10%로 효율이 가장 좋다. 예산이 200만 근처인 고객은 300만까지 채우면 적립이 1만원 → 11만원으로 뛴다. 판단 재료로만 쓰고(영업 아님), 억지로 더 사게 만들지 않는다.
  - **200만원 이하 지출 고객에게 적립은 주 혜택이 아니다**(200만원 지출 시 적립 1만원). 이 구간에선 환급 30,000P와 할인 쿠폰팩이 실제 주 혜택이므로 그쪽을 앞세우는 게 정직하다.

### 총 혜택은 계산기로

- 총 혜택은 쿠폰을 얼마나 쓰는지, 견적을 몇 개 신청하는지에 따라 달라진다. **직접 합산해서 말하지 말고 공식 '혜택 계산기'로 넘긴다.** 대표 페이지(https://ohou.se/moving-pass/intro)의 '혜택 계산기' 탭에 예상 쇼핑 지출과 계약할 이사 서비스를 넣으면 자동 계산된다. 상담사가 암산해서 틀릴 위험이 없고, 고객이 직접 본 숫자라 신뢰도도 높다.
- 일정표 안 '이사준비자료 > 멤버십혜택' 버튼의 연결 대상은 확인 전이다. 예전 링크(ztai61)로 연결돼 있으면 고객에게는 위 대표 페이지 링크를 따로 보낸다.

### 매칭 상태 조회 (상담사 권한 — 2R)

대행 접수 이후 상담사가 조회할 수 있는 필드:

| 필드 | 값 | 평시 고객 안내 |
|---|---|---|
| 매칭 상태 | 매칭 대기 / 매칭중 / 매칭완료 / 매칭실패 | ⭕ 이것만 알려준다 |
| 매칭된 업체 수 | 숫자 | 요청 시에만 |
| 매칭된 업체 이름 | 업체명 | 요청 시에만 |
| 업체 매칭 승인상태 | 수락대기 / 상담거절 / 상담진행 | 요청 시에만 |

**평시 원칙: 매칭 상태만 전달한다.** 업체 수·이름·승인상태는 고객이 직접 확인을 요청한 예외 케이스에만 꺼낸다. 먼저 흘리지 않는다.

이유:
- 업체 이름을 먼저 말하면 추천처럼 읽힌다. 업체 선택은 고객 몫이라는 경계가 무너진다.
- 업체 수를 먼저 말하면 적을 때 불안만 준다(지역·일정에 따라 원래 차이가 난다).
- '상담거절'을 그대로 전달하면 고객이 자기 건이 문제라고 느낀다. 업체 일정 사정이 대부분이다.

요청받아 승인상태를 전할 때는 **진행 중인 곳 위주로** 말한다. "한 곳은 거절, 두 곳은 대기"보다 "지금 두 곳이 진행 중이고 한 곳은 일정이 안 맞았어요"가 같은 사실의 정확한 전달이다.

### 이사업체 매칭 개수·재매칭 정책 (팀 확인, 정책서엔 없던 내용)
- 최대 4개(무조건 아님), 평균 3개 정도. 지역·일정에 따라 차이. 일정이 멀면(업체가 임박 건 우선) 적게 매칭될 수 있음.
